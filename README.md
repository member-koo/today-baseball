# 오늘의 야구 한판 — 2차 시제품

갤럭시에서 볼 수 있는 KBO 경기 전 프리뷰 웹앱의 기초 프로젝트입니다.

## 이번에 실제로 구현한 기능
- 공식 KBO 경기 일정 HTML을 조회해 해당 날짜의 경기 시간·팀·구장을 JSON으로 저장하는 수집기 (`update_data.py`)
- GitHub Actions 매일 16:00 KST 자동 실행 예약 (`.github/workflows/update.yml`)
- 형식이 예상과 다르거나 조회가 실패하면 이전 정상 파일을 보존하는 안전장치
- HTML 샘플을 이용한 오프라인 테스트

## 아직 구현되지 않은 기능
- 선발투수, 공식 선발 라인업, 선수 상대전적 수집
- 통계 기반 승패 및 예상 점수, 관전 포인트
- 실제 Web Push 구독/발송 및 배포

## 실행
```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
python update_data.py --date 2026-10-09
```

KBO 사이트의 실제 HTML 형식과 이용 조건을 추가로 확인해야 합니다. GitHub Actions 예약 실행은 정확한 시각을 보장하지 않으며, GitHub Pages는 이 파일만 올려도 자동 활성화되지 않습니다.

## v0.3
- KBO 홈페이지의 10개 구단 순위표를 검증한 후 KIA/한화 순위를 표시합니다.
- 공식 순위표 구조가 바뀌거나 10개 구단이 확인되지 않으면 추정값 대신 '미확인'을 표시합니다.
- 선발투수, 확정 라인업, 예측 점수, 푸시 알림은 아직 구현하지 않았습니다.
- GitHub Actions 자동 실행은 저장소 업로드 및 활성화 후에만 작동합니다.

## v0.4: 라인업 데이터 검증 계층

`lineup.py`는 날짜와 상대팀, 출처 URL, 확인 시각, 팀별 9명 명단을 검사합니다. 공식/예상 상태를 구분합니다. 출처가 확인된 JSON 파일이 없으면 명단을 표시하지 않습니다. **자동으로 KBO 라인업을 다운로드하는 기능은 아직 구현되지 않았습니다.**

테스트: `python -m pytest -q` (7개 통과). GitHub 예약 실행은 지연될 수 있으며 아직 배포/활성화되지 않았습니다.

## v0.5 데이터 신뢰성 보강
- `data_quality.py`: 한국시간 기준 당일 경기인지, 3시간 이내에 확인했는지, 공식 일정 URL인지 검증합니다.
- 웹 화면은 오래된 샘플 일정이 오늘 경기인 것처럼 표시되지 않도록 차단합니다.
- **중요:** 이 기능은 실제 외부 사이트 접속 성공을 의미하지 않습니다. 공식 선발/라인업 자동 수집과 푸시 발송은 여전히 미구현입니다.
- 수집 실패 시 이전 데이터 파일은 유지하지만, 화면에서는 오래된 정보라고 표시합니다.

## v0.6: 10개 구단 전체 지원
- 관심 팀을 10개 구단 또는 전체 경기 중 선택하여 볼 수 있습니다. 로그인·저장은 아직 없습니다.
- 경기 매치업 검증과 중복 방지 테스트를 추가했습니다.
- 예측 모델이 없는 경기는 **점수를 만들어 표시하지 않습니다**.
- 2026년 10월 14일 시작하는 포스트시즌은 별도 일정·예측 로직이 필요합니다. 현 수집기는 정규시즌 일정 페이지를 대상으로 합니다.
- 실제 KBO 접속/배포/푸시 발송은 아직 검증되지 않았습니다.

## v0.7: 실제 팀 기록이 확보되었을 때만 예측
- `prediction_model.py`: 팀별 경기 수·득점·실점으로 예상 스코어와 확률을 계산하는 **기초 통계 모델**.
- 선발투수, 확정 라인업, 개별 선수 상대전적은 **아직 모델에 반영되지 않음**.
- `data/team_stats.json` 파일이 없거나 출처·날짜·10개 팀 기록 검증에 실패하면 **예측 미표시**.
- 자동으로 팀 득실점 자료를 수집하는 기능은 아직 없음. 따라서 현재 배포 시 예측이 자동 생성되지 않음.
- `python -m unittest discover -s tests -v` 로 검증 가능.
- 경기 결과를 모르는 시점의 기록만 사용해 미래 데이터 유출을 차단.

## v0.8: 데이터 근거가 있는 관전 포인트
- `insight_engine.py`는 **검증된 예상 득점**이 있을 때만 득점 우위를 설명합니다.
- 공식 라인업이 없거나 선수 상대전적 데이터가 없으면 선수 이름을 만들어내지 않습니다.
- `update_data.py`가 경기마다 `insights`를 생성하고 웹앱에서 표시합니다.
- 현재 외부 KBO 자동 수집과 선수별 맞대결 연동은 검증되지 않았습니다.

## v0.9: GitHub 배포 준비
- `.github/workflows/pages.yml`: `main` 브랜치에 올리면 테스트 후 GitHub Pages로 정적 웹앱을 배포합니다. 저장소 Settings → Pages → Source에서 **GitHub Actions**를 선택해야 합니다.
- `.github/workflows/update.yml`: 매일 12:30 및 16:30(한국시간)에 수집을 시도합니다. GitHub 예약 실행은 지연될 수 있으며, 14시 경기는 12:30 수집 시 라인업이 아직 미공개일 수 있습니다.
- `tests/fixtures/kbo_schedule_sample.html`: 인터넷 없이 일정 추출을 검증하기 위한 **인공 테스트 데이터**입니다. 실서버 접속 성공을 의미하지 않습니다.
- KBO 원본 웹사이트의 접근 정책 및 구조 변경 가능성을 확인해야 합니다. 실제 자동 수집, 선발·라인업 연동, 예측 데이터, Web Push는 아직 검증/구현되지 않았습니다.
- 배포해도 `data/today.json`이 오늘 날짜가 아니면 화면은 최신 정보 대신 안내 메시지를 보여줍니다.

### 사용자에게 필요한 GitHub 작업 (배포할 때)
1. GitHub에서 새 **공개** 저장소를 만들고 압축파일의 `baseball-preview` 폴더 **안에 있는 파일 전체**를 저장소 최상위에 올립니다. `.github` 폴더도 포함해야 합니다.
2. 저장소의 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 선택합니다.
3. **Actions** 탭에서 `Test and publish preview website` 성공 여부를 확인합니다.
4. 배포 링크를 열어 시제품을 확인합니다. 최신 데이터 수집이 실패하면 실제 경기 예측은 표시되지 않습니다.

**보안:** GitHub 비밀번호·토큰을 채팅에 보내지 마세요. 실제 푸시 알림은 별도의 서버/서비스 구성이 필요합니다.
